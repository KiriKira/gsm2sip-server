# 三端 WebRTC 通话迁移计划

> 2026-10-19：分支已实现独立 Go/HTTPS 呼叫控制、两端原生 WebRTC 和可选 SIP 兼容；三个节点关闭 Asterisk 的呼出/呼入长通话、通话控制、拒接/取消与零 SIP/ARI 抓包已通过。其余媒体/控制故障、多节点与兼容验收继续执行，尚未发布新独立控制 Release。[实现、协议与部署](rtc-call-control-v1.md)。下文旧阶段状态按记录日期阅读。

更新：2026-10-16。状态：W0 基线和 W2 接缝/协商模块部分完成，W1 隔离媒体探针已构建；
真机 PCM/TURN、生产信令接入及 WebRTC 通话尚未完成，仍默认 SIP。
实际进度及验证记录见 [迁移实施记录](webrtc-migration-status.md)；本文的目标接口、配置和阶段不表示均已可用。

目标：将主机、网关和服务器的通话信令/媒体从 SIP + Asterisk 迁移到 WebRTC，保持现有 UI 和外围功能的可观察行为。
直接以现有 SIP 实现作为对照和迁移期回退路径，不先实现另一套自研 SIP/B2BUA。
本文取代 [旧自研 SIP 计划](plan-native-sip.md) 的后续实施路线；既有协议仍以
[wire addendum](server-wire-addendum.md) 与 [OpenAPI](../openapi/openapi.yaml) 为准。
新增 WebRTC wire 契约在 W2 单独冻结并纳入同一套协议文档、schema 和 fixtures，禁止两端各自定义。
已实现协商子模块及其未接入边界见 [RTC v1 实验契约](rtc-signaling-v1.md)；该契约尚未发布为网络端点。

## 1. 范围与不可退化的边界

“UI 不受影响”包含布局、文案、导航、按钮可用性、通知操作、通话历史和用户设置语义，不只是截图相似。
允许调整页面背后的数据适配和依赖注入；不得把本次迁移扩展为界面重构或要求用户重新配置已有功能。

| 范围 | 必须保持的行为 |
|---|---|
| 主机 UI | 电话/短信/设置导航、拨号盘、来电/通话页面、联系人、折叠屏适配、通知接听/拒接、静音、DTMF、音频路由及历史记录保持一致 |
| 网关 UI | 设置步骤、SIM 确认、状态显示、后台开关及诊断入口保持一致；不能因删除 SIP 类让控件失效 |
| 短信 | HTTPS 命令与事件、journal/ledger、跨节点 message_id 去重、分片回执、unknown 不补发、游标/ACK、OTP 通知和草稿保持原语义 |
| 身份与数据 | 一次性配对、令牌刷新/撤销、Keystore、owner/device 隔离、SIM ID 与节点内 revision、备份/导入和本地数据保持兼容；升级无需重新配对 |
| 多节点 | 独立服务器、逐节点会话、用户排序、健康探测/防抖、短信跨节点去重和通话中锁定节点保持一致 |
| 后台 | 保留现有前台服务、通知渠道、熄屏/重启恢复、锁屏来电、音频焦点及权限时序；已有支持能力不得退化，原有未验收能力不能因此宣称完成 |
| 蜂窝执行 | 网关仍是唯一蜂窝执行者；全局同一 call_id 最多拨号一次；网关同一时刻一通蜂窝通话；不回落默认 SIM |

本次不做：节点间数据库复制/信令转发、SFU/会议/录像、第三方 SIP 终端支持、短信改走 DataChannel、
新增推送平台、UI 改版、账户合并或音频 HAL 通用重写。WebRTC 不改变设备的双卡/DSDS 硬件限制。
新引擎开关属于管理员配置或开发测试配置，不在 App 新增用户必须操作的开关、TURN 输入框或配对步骤。

## 2. 当前耦合与改造接缝

| 部位 | 当前实现与风险 | 本次接缝 |
|---|---|---|
| 主机能力与页面 | MainActivity 调用 getSipConfiguration、反射 SipEngineFactory；CallRuntime/CallPreferences 依赖 sipAvailable | 增加协议无关的能力/引擎适配，向现有页面输出同一视图模型；先覆盖旧行为再替换底层 |
| 主机通话 | SipEngine、HostCallService、CallSessionCoordinator、CallTelecomController | 提取 CallEngine（拟定名），SIP 适配器与 WebRTC 实现并存；保留 coordinator、Telecom、通知和前台音频授权边界 |
| 网关音频 | CallOrchestrator 与 RtpSession 同时负责 SIP/RTP、选卡、蜂窝音频和通话状态 | 分离通话传输与 CellularAudioBridge（拟定名）；保留 GsmCallManager、root broker、音频配置及物理 SIM 校验 |
| 网关生命周期 | GatewayService 同时运行控制同步、mesh 与语音；stopGateway 会停止控制循环和整个服务 | 增加只停止语音的路径；PeerConnection/ICE/TURN 故障不得进入整个网关停止或清除配对流程 |
| 服务器 | internal/calls 依赖 ARI channel/bridge 事件和 endpoint ID | 保留呼叫授权、占用、participants、状态 revision、历史及 owner scope，增加通话传输适配；不能把 ARI 事件名直接当 WebRTC 状态 |
| 唤醒连接 | /v1/ws 只发 sync_required，拒绝客户端应用数据帧 | 原端点完全保留；新增独立通话信令通道、连接预算和队列，不占用短信游标或 ACK |

W0 必须列出所有可见 SIP 设置、诊断与状态字段的映射表。过渡期保留旧配置及其存储，不把
`sip_registered` 伪装成 WebRTC 已注册，也不为通过旧判断返回虚假的 SIP 凭据。
新客户端在兼容层把各协议的真实能力映射为现有 UI 状态；旧客户端仍读取真实 SIP 状态。
若某个可见设置（例如旧编码选择）在 WebRTC 下没有等价语义，必须在默认切换前解决映射；
不得静默忽略、删除控件或以“后续改 UI”作为本次完成条件。未解决则阻止默认切换和旧引擎移除。

## 3. 目标架构与部署

```text
主机现有 UI / CallRuntime / Telecom / 通知
                 │ CallEngine
                 ▼
          Android WebRTC 端点
                 ║ DTLS-SRTP（直连或 TURN 转发）
          Android WebRTC 端点
                 │ CellularAudioBridge
                 ▼
网关现有蜂窝控制 / SIM 校验 / PCM 采集与注入

两端 ── 独立的通话信令连接 ── 当前选定的 Go 服务器 / PostgreSQL
两端 ── 既有 HTTPS + wake-only WSS ── 短信、配对、事件与状态
```

- 首版为两部手机间的 WebRTC 音频 PeerConnection；ICE 直连优先，TURN 为必要的中继路径。
  服务器负责认证、呼叫状态和信令转发，默认不终止媒体、不解码/转码音频。
- Go 信令服务不需要为了转发 JSON 而引入完整 pion/webrtc。Pion 可用于测试端点；
  独立 coturn 为初始 TURN 选型，固定经验证版本。内嵌 pion/turn 是单独权衡，不同时维护两套生产中继。
- API/WSS 使用服务器部署的 HTTPS 入口。TURN 使用独立、两端可达的监听地址与证书，
  配置 UDP/TCP/TLS 接入及实际 relay 端口范围、NAT 映射和防火墙。首版不依赖与 HTTPS 共用同一 IP:port。
- TURN/TLS 只保证客户端到 TURN 的对应传输，不能据此认定所有网络路径可用；W1 必须强制 relay
  验证双向音频。服务器只开放 API 端口不等于媒体可用，注册/ICE 成功也不等于蜂窝音频可用。
- TURN 凭据短期有效，受已认证且被授权的设备/呼叫约束；配置分配数、带宽、过期回收和目的地址限制，
  禁止匿名中继及借中继访问管理网段。长通话覆盖凭据到期、allocation refresh 和 ICE restart 的行为。
- API 数据库就绪、语音信令就绪、TURN 探测及端到端音频分别报告。语音未就绪时不把短信 API 标为不可用。
- 公网新信令采用 HTTPS/WSS。保留已有可信局域网 HTTP 配置的兼容流程；该模式不新增默认入口，
  DTLS-SRTP 也不能弥补明文信令中指纹被替换的风险。需要变更用户部署地址时不得以重新配对掩盖迁移问题。

Android SDK 在 W1 固定来源、上游提交、工具链、ABI、校验和、许可证及构建步骤；不凭包名或最新版本号选型。
检查 minSdk 26、目标系统、arm64-v8a、16 KB page size、JNI 符号冲突、包体和内存。
过渡期允许同包包含两套引擎以支持回退，但同一通电话只能启动其中一套，不能争抢麦克风/焦点。

## 4. 网关 PCM 与音频生命周期：第一道可行性门槛

先验证自定义 AudioDeviceModule 或同等的双向 PCM 接入能力：编码前注入蜂窝下行 PCM，
解码后把远端 PCM 送入现有蜂窝上行路径。只拿到录音回调、只能采集默认麦克风或只能播放扬声器都不算通过。
若 SDK 的公开接口不够，记录所需的最小 native 扩展、可重复构建及维护成本，验证成功前不推进三端大面积重写。

必须验证：

1. 保留目标设备已验证的音源、AudioTrack 路由、Magisk/root 适配和启动顺序；WebRTC 不授予蜂窝音频权限。
2. 明确每条路径的采样率、声道、PCM 格式与帧时长。设备 8/16 kHz 与 WebRTC 内部/Opus RTP 时钟分别处理；
   不通过修改采样率标签替代重采样。使用有界缓冲，记录 underrun/overrun、漂移与延迟。
3. 主机由 Telecom 统一管理音频焦点和端点；SDK 不另建蓝牙 SCO 或覆盖用户选择。
   网关不能按普通 VoIP 麦克风/扬声器模式覆盖蜂窝路由。
4. AEC/AGC/NS 按实际路径选择，避免双重处理或抵消干净的蜂窝下行；先与关闭处理的基线比较。
   不预先承诺 WebRTC 能消除既有噪声。
5. 保留静音的真实媒体效果。用户接听授权、前台服务及所需权限就绪前，不开放采集或把音频送给候选接听者。
6. DTMF 明确从主机操作、WebRTC telephone-event 到网关蜂窝控制的映射；验证长按/释放、去重、挂断取消，
   必须在真实 IVR 验收，不能以本地按键音或收到 RTP 包代替。
7. 释放顺序覆盖媒体线程、PCM 缓冲、音频路由、Telecom 和唤醒锁；迟到回调带运行代次，不能重开已结束通话。

## 5. 信令契约与状态一致性

以下是 W2 必须落实到 schema、OpenAPI/协议说明和 fixtures 的要求，不是已发布的 wire 字段。
协议版本独立于现有短信协议，新增字段采用向后兼容的能力声明；不改变现有 /v1/ws 帧格式。

### 身份、顺序和恢复

- 独立信令端点验证现有设备会话；每个操作绑定节点内 owner/device/gateway、call_id、SIM 与 mapping revision。
  install_id 用于关联同一安装，不作为授权秘密，客户端自报身份不能覆盖服务端 principal。
- 一通呼叫的 call_id 跨重试保持不变；每个参与者/协商尝试另有 leg/attempt 标识，
  每次 SDP/ICE restart 递增 generation，操作使用独立去重键。相同键不同负载必须拒绝。
- offer/answer、candidate、end-of-candidates、接听/拒接/挂断必须有明确的发送者权限、状态前置条件、
  revision/顺序、有效期和 ACK 语义。初始 offer 由固定角色生成；重协商指定单一发起者并定义冲突处理。
- candidate 只用于对应 leg 和 ICE generation；早到 candidate 有界暂存，旧 generation 丢弃，
  没有匹配 remote description 时不跨通话套用。SDP 大小、candidate 数和速率均有限额。
- 呼叫控制状态和关键操作 ACK 在数据库提交后返回；短期媒体协商数据与短信存储分离并设置 TTL。
  重连先读权威快照再恢复缺失的有效信令；无法证明协商完整时新建协商 generation，不盲目重放所有历史消息。
- 信令断线不是重新拨号理由。ICE disconnected、failed、协商超时和控制授权过期分别定义恢复期限；
  不能确认授权时暂停音频并在期限内收敛。短暂切网允许原 call 的 ICE restart，不更换 call_id 或重新执行蜂窝拨号。
- ended/unknown 等终态不得被迟到 answer、candidate、ACK 或重连恢复为活动状态。
  设备撤销/切换账户会关闭相关通话权限，不能只关闭 WSS 而放任已建立的直连媒体无限继续。
- SDP fingerprint 及 ICE 参数绑定同一已认证、已授权的 leg/generation，保留 DTLS 校验；
  不将 DTLS-SRTP 描述为能够防御受信信令服务器本身被攻陷。普通日志不输出 token、完整 SDP、ICE 密码或完整号码。

### 去电

1. 用户沿用现有页面选择 SIM/号码；主机创建并持久化该次呼叫身份，再申请服务器授权。
2. 服务端校验 owner、设备、SIM revision、占用和双方能力，选定引擎/节点；创建 intent 本身仍不得拨打蜂窝电话。
3. 两端完成受授权的媒体准备；网关在执行前再次校验 intent、物理 SIM、有效期和全局执行账本。
   未准备好可用媒体路径时不提前触发计费拨号。
4. 网关先持久化 dispatch 决策再调用蜂窝拨号；崩溃/响应丢失后查询系统通话与账本，无法判断时记 unknown，绝不自动重拨。
5. 蜂窝振铃和实际应答驱动现有振铃/接通状态。只有蜂窝 ACTIVE、媒体可用和授权均满足才呈现 ACTIVE 并启动通话计时。

### 来电、多主机和终止竞态

1. 网关在真实蜂窝呼入时创建全局 call_id，沿既有已配对节点分别上报；每个节点仍只通知自己的授权参与者。
   主机去重后创建一次现有 Telecom/通知会话，唤醒或 SDP offer 本身不能接听蜂窝电话。
2. 用户接听后可建立有期限的候选 reservation，准备媒体和前台音频权限。reservation 不等于 winner，
   失败/超时释放；媒体准备阶段不得把蜂窝音频扇出给所有候选。
3. 所有节点的候选都到网关唯一裁决入口：单一串行执行器配合持久化全局占用和 fencing generation，
   原子确认一个具备有效授权、用户接听动作及可用媒体路径的 winner。服务器单节点行锁不能替代跨节点裁决。
4. winner 持久化后，网关最多一次执行蜂窝接听并开放 winner 媒体；蜂窝 ACTIVE 后各端收敛为活动通话。
   如果此时失败，明确结束并释放资源，不把已取消的候选静默恢复为接听者。
5. 其他候选得到现有 answered_elsewhere 结果并停止响铃。单个拒接只终结该参与者；全部拒接/过期才结束该次呼入。
6. 网关按节点持久化必要的终态投递/重试记录，节点恢复后校正历史。网关重启先与系统通话核对，
   无法确定 winner 或执行结果时失败关闭；不从网络旧消息再次接听/拨号。
7. 挂断、拒接、超时、远端结束均幂等；重复通知不重复产生历史行。网关单通话占用不因控制连接短断而提前释放。

### 对现有展示状态的映射

| 底层事件 | 现有用户状态/规则 |
|---|---|
| 授权和通话传输准备 | 保留现有申请授权/准备阶段，页面不直接观察 PeerConnection 枚举 |
| 蜂窝拨号/振铃 | DIALING / OUTBOUND_RINGING |
| 有效来电与用户接听 | INCOMING_RINGING / ANSWERING |
| ICE/DTLS connected | 仅表示媒体传输条件满足，不能单独映射 ACTIVE |
| 蜂窝 ACTIVE + 媒体可用 + 有效 winner/授权 | ACTIVE；再更新 Telecom、计时和历史 |
| 短时 ICE 断线 | 按有界恢复策略处理原 call，不重复拨号、不重复来电通知 |
| 终止/错误 | 映射现有 ENDED/FAILED 和结束原因，统一释放通知、音频及占用 |

## 6. 多节点和新旧版本兼容

保留每节点会话、设备 ID、SIM revision、健康探测及优先级。新协议可单独上报语音能力，
但不得把 TURN 探测失败变成短信节点不可用，也不修改 NodeSelectionPolicy 的既有切换语义。
活动通话锁定节点；媒体可以在同一通话内重新 ICE 协商，但首版不迁移通话控制到另一台服务器。

服务器和两端显式声明支持的协议版本。新服务器保留旧 SIP 接口、凭据和 ARI 适配，
新 Android 版本在过渡期保留 SIP 适配器。未知能力按旧端处理，不让旧端解析新信令。

| 组合 | 迁移期预期行为 |
|---|---|
| 旧服务器 + 新两端 | 使用原 SIP 路径；短信和配对不变 |
| 新服务器 + 任一旧端 | 使用原 SIP 路径；新功能不可用不等于账户失效 |
| 新服务器 + 新两端且协议兼容 | 按管理员策略选择 WebRTC，缺少能力时在新呼叫开始前选 SIP 或明确报告语音不可用 |
| 来电候选包含旧主机/旧节点 | 首版整通来电使用 SIP；能力未知也走此兼容策略，避免一通呼入跨两种引擎竞争接听 |
| 纯 WebRTC 部署收到旧端请求 | 明确返回语音能力不兼容，既有短信/配对继续可用；旧端仍在支持范围时禁止切到此部署 |

引擎选择在 call 创建/来电分叉前确定并持久化；call_id 在两种引擎间共用去重与网关占用。
呼叫中不能因超时自动改用 SIP 再拨一次，来电的参与者集合及兼容决策也不能在振铃途中随意改换引擎。
节点间信令转发、互信、跨节点通话控制迁移另立计划；本次完成不以这些新增功能为前提。

## 7. 分阶段实施与完成门槛

每阶段独立 PR，记录三仓库 SHA、SDK/系统版本、实际执行命令和本次运行产物；未通过门槛不推进默认切换。
表中任务均为待完成，不能引用旧 SIP 测试通过来标记 WebRTC 已完成。

| 阶段 | 改造范围与交付 | 完成门槛 |
|---|---|---|
| W0 行为基线 | 三端固定提交；枚举页面/设置/数据/权限契约和当前缺陷；录制 UI、双卡通话与后台流程；锁定发布签名、数据库样本和回退版本 | UI/外围清单有对应测试；既有未验收能力显式标记；协议专用设置有可行映射 |
| W1 媒体与网络探针 | 固定 Android SDK；隔离探针验证网关 PCM、自定义音频接入、Opus、DTMF、TURN UDP/TCP/TLS 和拒绝非法证书 | 两卡分别验证双向真实数字音频；强制 relay、无 UDP 网络路径可用；记录噪声/延迟/资源基线，否则停止扩大重写 |
| W2 接缝与契约 | 三端通话接口、SIP 兼容实现；独立信令 schema/fixtures、状态机、能力协商、网关裁决/账本和数据库增量迁移设计 | 仍用 SIP 的端到端行为不变；信令鉴权/乱序/过期/幂等及全局抢接模型测试通过；所有关键超时、队列上限写入契约 |
| W3 单节点集成 | 新信令端点、Android 引擎与音频桥、Telecom 状态映射；开发配置下启用 WebRTC | 两卡去电/来电、主机抢接、拒接/超时/挂断、DTMF和强制 relay 端到端通过；故意破坏语音时短信继续正常 |
| W4 多节点与恢复 | 保持原拓扑的跨节点去重/单通话裁决；混合版本、切网、断连、进程/服务重启和后台场景 | 无重复拨号/双接听/幽灵响铃；原节点排序、配对和短信行为不变；所有升级矩阵组合通过 |
| W5 灰度默认切换 | 服务端策略控制指定设备/部署的新呼叫；采集不含敏感内容的指标；演练回退 | UI 和外围回归、真机持续运行、性能门槛及回退演练全部通过；扩大范围前每批检查结果 |
| W6 移除旧引擎 | 仅在兼容窗口关闭后移除 Asterisk/ARI、SIP 媒体依赖与过时部署项；保留仍被现有页面/数据读取需要的兼容适配 | 至少保留一个已发布版本的回退窗口，支持范围内无旧端；所有设置语义已解决；去除旧依赖后重新通过完整验收 |

W0–W2 可分别做文档、探针和无行为变化的适配；W1 未通过不得把 UI 或业务层一起重写。
每个代码 PR 必须说明是否触及页面、Manifest/权限、通知、数据库、短信或后台生命周期；
涉及这些边界时附相应回归证据，不能用“仅换引擎”免除验证。

| Android 生命周期 | API 26 与目标现代系统、锁屏/Doze、拔充电器、重启、进程终止、麦克风/通知权限拒绝与撤销、蓝牙/有线/扬声器切换、本机蜂窝电话抢占；SMS-only 不启动音频或请求额外权限/root |

复用现有 Go/PostgreSQL 集成测试、协议检查、两端 :app:testDebugUnitTest 和 :app:assembleDebug，

## 9. 灰度、迁移与回退

- 先发布保持 SIP 默认的新服务器和兼容客户端，再按设备/部署对新呼叫启用 WebRTC。
  策略变更不影响正在进行的通话；进入维护时先停止新呼叫并等待已有通话结束或明确结束。
- 数据库先新增可空/有默认值的字段和新表，保留旧字段及凭据；旧二进制可读写性必须实测，
  检查当前 migration runner 对新版本记录的行为，不能仅凭“增量 migration”推断能回退。
- WebRTC 模式按持久化的引擎标识恢复原 call；旧 ARI 恢复器不得把 WebRTC 会话误判为悬空 SIP 通话并清理。
  节点健康和历史查询也必须认识两种传输，保持现有响应语义。
- 回退先禁用新 WebRTC 呼叫，排空/明确结束活动通话，再恢复经验证的兼容版本和策略；不自动重拨。
  对无法读取新数据的旧版本，只能使用已验证的兼容回退版本，不能直接启动或在在线数据库上破坏性降级。
- 保留应用签名、配对、Keystore、用户偏好、短信账本、通话历史与节点配置；不得靠卸载重装回退。
  回退包、数据库样本、步骤、持续中的短信任务验证结果随灰度发布一起留档。

## 10. 风险决策与阶段责任

| 风险 | 负责实现的端 | 解除条件 |
|---|---|---|
| UI 对 SIP 的依赖、旧设置无等价语义 | 主机/网关，服务端提供能力契约 | W0 设置清单、W2 兼容适配和 UI 基线验证；未解决不得默认切换 |
| 自定义音频接入、设备路由或双重 AEC 导致单向/静音 | 网关为主、主机配合 | W1 PCM/DTMF 真机探针和 SDK 可复现构建 |
| 语音生命周期影响短信/后台 | 两端服务层 | W2 隔离与 W3 故障注入，控制同步继续运行 |
| 乱序、旧协商消息或跨节点重复执行 | 服务端及网关账本，主机遵循契约 | W2 状态机与 W4 跨节点/重启竞态测试 |
| TURN 可达性、费用和 TCP 队头阻塞 | 服务端部署、两端媒体 | W1 强制 relay，W4 网络矩阵与容量/长通话验证 |
| 混合版本、旧 ARI 恢复器或数据库回退损坏状态 | 三端共同负责 | W4 升级矩阵与 W5 回退演练 |

W1 必须决定 SDK pin、PCM 接口、ABI 和 TURN 版本；W2 必须决定 wire 路径/版本、超时/配额、
授权续期、winner 裁决和兼容能力字段。未决项有实验记录和阶段门槛，不把猜测写成已交付能力。
