# 多节点（mesh）运行

更新：2026-10-12。本文是多台独立服务器同时服务同一台旧手机的设计依据。
协议字段以 [wire addendum](server-wire-addendum.md) 与 [OpenAPI](../openapi/openapi.yaml) 为准。

## 前提与目标

- 旧手机（网关）始终在家并在线；宽带断开时用旧手机自己的移动数据。
- 部署多台**互相独立**的服务器节点（各自的 PostgreSQL 与 Asterisk），例如家里的 Arch Linux
  （局域网或私有网络直连）和若干 VPS。节点之间不复制数据库，也不选主。
- 主手机按用户拖动排定的优先级使用节点：当前节点不通或质量差就切到下一个，更高优先级的
  节点恢复后切回。
- 保证：
  1. 主手机不会因为同一条短信或同一通来电经过不同节点而收到两次；
  2. 同一条发出的短信，无论经过几个节点、重试多少次，旧手机最多执行一次；
  3. 电话不冲突：旧手机同一时间只桥接一通电话，同一次呼叫不会被拨两遍。

## 核心原则：ID 在两端铸造，执行只在旧手机发生

| 对象 | 谁铸造 ID | 各节点上是否相同 |
|---|---|---|
| 入站短信 `message_id` | 旧手机 | 相同（已有行为） |
| 出站短信 `message_id` | 主手机（`mesh` 扩展） | 相同 |
| SIM `sim_id` | 旧手机提议（`proposed_sim_id`） | 相同 |
| 旧手机身份 `install_id` | 旧手机 | 相同 |
| 入站来电 `call_id` | 旧手机（已有行为） | 相同（第二阶段经多节点分叉） |
| 节点内设备 ID、`mapping_revision`、命令 ID、事件游标 | 各节点 | 各不相同，只在本节点内有意义 |

服务器只负责暂存、转发与唤醒；旧手机的 SQLite 账本是唯一执行记录：

- 出站短信：账本以 `message_id` 唯一。另一个节点为同一 `message_id` 下发的命令被登记为
  该执行的别名，绝不再次调用 modem；内容不同则拒绝。dispatching 之后结果不确定仍标
  `unknown`，不自动重发。每 SIM 的发送限额也记在旧手机本地，对所有节点合计生效。
- 入站短信：旧手机只在本地记一条，再为每个节点各生成一份事件（`message_id` 相同，
  `sim_id` 相同，`mapping_revision` 与事件 ID 按节点区分），分别上传、分别确认。
  正文在所有节点都确认后才从本地清除。
- 主手机把所有节点的数据合并进**一个**本地库，按全局 `message_id` 去重；通知也按它去重，
  所以同一条短信经过几个节点都只提醒一次。事件游标与确认按节点分别保存。

## 节点选择（主手机）

- 节点列表可拖动排序；每个节点单独配对（各自的配对码与会话）。加入节点时检查其
  `/gateways` 返回的 `install_id` 与已有节点一致，不一致即拒绝，避免把两台旧手机的数据混在一起。
- 健康探测：`GET /v1/capabilities`（公开，测往返时间）与已认证的 `GET /v1/gateways`
  （确认旧手机在该节点上在线）。连得上但看不到旧手机在线的节点视为不可用。
- 切换：当前节点连续失败或延迟持续超过阈值时切到下一个可用节点；更高优先级节点需
  连续多次健康才切回（防抖）。正在提交短信时不切换；第二阶段起通话中锁定节点。
  网络变化（连上家里 Wi-Fi 等）立即重新评估。
- 发短信时把 `message_id` 先写入本地任务；若提交在当前节点失败而切到其他节点，用同一个
  `message_id` 重新提交，旧手机保证只执行一次。

## 节点网络与通话能力

服务器按实际部署配置 API、SIP 和媒体端口，节点能力由两部手机的实际可达性决定，与部署位置无关。
当前版本的 API 可通过 HTTPS 反向代理提供；SIP/TLS 和 RTP/SRTP 需要独立配置监听、端口映射与防火墙。
只开放 API 的节点可以承载短信、事件和状态同步，不能仅据此认定通话可用。
节点的语音注册状态按节点分别上报（`sip_registered`）；注册成功也不能代替双向音频验收。
旧手机在主节点启用语音后会自动为每个节点开通 SIP 端点。
在可信局域网或 Tailscale 内也可使用 `SIP_TRANSPORT=udp` 和 `http://` 直连，
见 [用预构建镜像部署](deploy-images.md)。主手机离开该网络后按原有规则探测和切换。

以上描述当前 SIP 实现。后续按 [WebRTC 迁移计划](plan-webrtc.md) 替换通话传输，
保留独立节点、排序、配对、短信去重和通话中锁定节点的行为；本次不增加节点间信令转发。

## 分阶段

1. **短信（本阶段）**：服务器 `mesh` 扩展（客户端 `message_id`、`proposed_sim_id`、
   `install_id`、`/capabilities`）；旧手机多节点会话、入站多节点分发、出站跨节点去重；
   主手机节点列表、探测与切换、合并本地库、跨节点重提交。
2. **电话（已实现）**：服务器 `mesh` 扩展接受客户端 `call_id`（`POST /call-intents`，重复返回
   `409 CALL_ID_CONFLICT`）；主手机在多节点配置下铸造呼出 `call_id`，旧手机通话账本以它唯一；
   旧手机在每个节点开通并注册 SIP，来电向所有节点分叉、首个接听者胜出并 CANCEL 其余；主手机
   只在当前节点注册 SIP，通话中不切换节点。
3. **一致性与体验（已实现）**：
   - 短信状态：主手机切到其他节点后，仍用各节点自己的会话向“发出该短信的节点”查询未结束短信的
     后续状态（送达/失败），合并进同一收件箱。
   - 一次扫码加入多个节点：在每个节点上为同一角色各生成一个配对码，用
     `scripts/mesh-join-link.py --role client|gateway URL=CODE ...` 合成一个
     `gsm2sip://join?...` 链接并打印二维码；手机相机扫码即打开应用，未配对时与第一个服务器配对、
     其余加为节点，已配对时全部加为节点。链接在配对码用掉或过期前属于机密。
   - 节点质量：主手机记录每个节点最近 20 次探测，显示可用率、中位延迟、是否可通话（旧手机在该
     节点已注册 SIP），点开节点看详情；旧手机的“其他节点”列表显示各节点通话注册状态。
